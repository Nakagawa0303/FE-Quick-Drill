# FE Quick Drill

基本情報技術者試験 科目A・科目B向けの静的な演習アプリ。HTML / CSS / JavaScript ES Modulesのみで動きます。アカウント、バックエンド、外部APIは不要です。配信時のビルドも不要です。

## ローカルで使う

```sh
python -m http.server 8000
```

ブラウザで http://localhost:8000 を開いてください。ES Modulesを使用するため、HTMLファイルの直接起動（file://）では利用できません。Node.jsを導入済みなら `npm start` でも起動できます。

## 使い方

- 科目・分野・出題数を選んで演習開始。問題が足りない場合は利用可能な数に減らし、画面で案内します。
- 数字キー1〜9または選択肢をタップして解答。左右矢印・前後ボタン・問題番号で移動し、解答を変更できます。自動で次には進みません。
- 最終問題から採点。未解答は確認の上、不正解として扱います。不正解の解説を先に開き、正解の解説は折りたたみます。
- 不正解は復習対象へ自動追加。正解問題にも要復習マークを付けられます。復習対象は正解後も維持し、マークを押して解除します。
- 中断ボタン、タブ切り替え、ページを閉じる操作に対応。再アクセス時にホームから再開できます。経過時間は画面を表示して演習した時間で、バックグラウンド・中断中は計測しません。
- 学習記録からJSON書き出し・復元。復元は10MBまで。形式・バージョン・問題ID・選択肢・成績の整合性を検証し、確認後に全件を置き換えます。取り込む前に現在のデータを書き出すことを推奨します。
- 演習・採点結果・過去結果に科目／大分野／小分野を表示します。小分野は[IPAシラバスVer.9.2](https://www.ipa.go.jp/shiken/syllabus/omgdg50000005kpe-att/syllabus_fe_ver9_2.pdf)の**中分類相当**であり、公式の小分類とは異なります。科目Bは従来の2分野を使います。
- 学習記録を科目（すべて／A／B）・大分野・小分野で絞り込めます。科目Aでは大分野を選ぶ前にも全小分野から選べます。科目変更で大分野・小分野、大分野変更で小分野がリセットされます。科目「すべて」は下位条件が無効、Bは小分野を表示しません。
- 概要・分野別・問題別・最近の演習は同じ条件で集計します。分母は採点済みの解答回数（繰返しと採点された未解答を含み、中断中は除外）。0件は「—／未学習」。過去の履歴も問題IDから**現在の分類**に照合し、分類のないA問題は「未分類」として残します。最近の演習は一致分の成績を表示し、解説から元の演習全体を開きます。絞り込んだ解答の時間は記録していないため表示しません。
- 分析条件はメモリ内だけで管理し、出題条件や学習履歴へ書き込みません。保存キー `fe-quick-drill:v1` と `version:1`、settings／review／history／activeの形式は維持しています。

記録は同じオリジンの `localStorage`（キー `fe-quick-drill:v1`）に保存します。プライベートモード・ストレージ制限・ブラウザデータの消去により保存できない／消える場合があります。保存失敗は画面で通知します。別端末への自動同期や複数タブでの同時編集には対応していません。出題回数と正答率は採点済みの全履歴から集計します。

## ファイル構成

```text
index.html           画面の土台
css/style.css        レスポンシブデザイン
js/app.js            画面・操作・タイマー・JSON入出力
js/core.js           データ検証・出題・採点・集計（DOM非依存）
js/classification.js  科目・大分野・小分野の共有辞書、分析条件
js/storage.js        localStorage入出力
data/questions.js    既存サンプルと追加問題の結合
data/additional-questions.json  追加問題の編集用JSON
data/additional-questions.js    検査後に生成する配信用データ
js/question-bank.js  JSONバンクの検査・直列化
scripts/build-questions.js     問題検査・変換コマンド
docs/question-data.md          調査結果・IPA収録手順
tests/               出題・採点・復元・画面操作フローのテスト
```

## 問題を追加する

`data/additional-questions.json` の `questions` 配列へまとめて追加し、次を実行します。

```sh
npm run questions:build
npm run questions:check
npm test
```

Node.js 20以上が必要です。問題追加時だけJSONを検査して静的JSへ変換します。配信時のビルド・外部APIは不要です。JSONと生成された `data/additional-questions.js` を一緒にコミットしてください。

[データ構造・6要件の調査結果・検証方法・IPA収録手順](docs/question-data.md) に必須フィールドと公式利用条件をまとめています。新規の検証済み問題には正答と両解説の確認記録が必須です。検査だけで問題を検証済みに変更することはありません。未検証問題は通常演習・復習ともに除外します。

問題JSONは学習記録のJSONとは別形式です。既存サンプルのID・正答・保存形式は維持しています。

## GitHub Pagesで公開

1. このフォルダの内容をGitHubリポジトリにpushします。
2. リポジトリの Settings → Pages → Build and deployment で Deploy from a branch を選択します。
3. 公開ブランチと `/ (root)` を指定し保存します。
4. 表示されたGitHub Pages URLを開きます。

すべて相対パスなのでプロジェクト配下のURLでも動作します。`.nojekyll` 同梱、ビルド設定や秘密情報は不要です。公開URLとlocalhostではブラウザ保存領域が別になるため、移行にはJSON書き出し・復元を使ってください。
