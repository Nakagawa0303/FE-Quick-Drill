for (tを1からkまで1ずつ増やす)

```

### 問2：アルゴリズム・プログラミング（ARR-B-LOWERBOUND-002）

```

ウ．data[middle] ≧ target

### 問4：アルゴリズム・プログラミング（ARR-B-SPARSE-004）

## 正答・解説・検証結果

### 問1：正答 イ

先頭を退避し、左から右へ順に一つずつ詰める。これをk回繰り返す。

左詰めではdata[i + 1]を読む前に上書きしないよう、iを1からn - 1へ増やす。末尾に退避した先頭値を格納すれば左1個分の循環移動になり、k回で左k個分となる。アは右側から上書きするので、後続の読取りに使う値を壊す。ウはi=nでdata[n+1]を参照する。エはdata[1]を更新しない。k=0では外側ループが0回で、配列は変化しない。例は1回後{7,2,9,5,4}、2回後{2,9,5,4,7}となる。

参考にした既存問題：IPA-FE-2026-KOUKAI-B-001。変更点：右1個分の移動から左k個分へ変更し、上書きの方向とk=0の扱いを問う。

機械検査：154ケース。選択肢ごとの合格数（ア〜エ）：89 / 154 / 22 / 88。正答のみ全ケース一致。

### 問2：正答 ウ

target以上なら候補を保存し、さらに左側に最初の該当位置がないか探す。

ウが正しい。data[middle]がtarget以上ならmiddleは候補であり、より左の候補を探索する。target未満ならmiddle以前は全てtarget未満なので右側へ進む。各反復で探索範囲は必ず縮小する。アは大小の判定が逆方向になる。イはtargetと同値の要素を除外する。エはtargetそのものが存在しないがtargetより大きい値がある場合に候補を保存できない。例えば{1,3,3,8}にtarget=3なら2、target=4なら4、target=9なら5。空配列ではループを実行せず1を返す。

参考にした既存問題：IPA-FE-2022-SAMPLESET-B-013。変更点：一致探索の不具合判定から、重複・空配列を許す下限位置探索へ変更。

機械検査：3234ケース。選択肢ごとの合格数（ア〜エ）：182 / 1974 / 3234 / 1690。正答のみ全ケース一致。

### 問3：正答 ア

LIFOで1を取り出す。満杯でのpush(9)は失敗し、次に取り出すのは3。

スタックを底から頂上の順に書くと、{6}→{6,1}→{6}→{6,8}→{6,8,3}となる。この時点で満杯なのでpush(9)はfalseを返し、内容とtop=3は不変。その後pop()は3を返し、{6,8}、top=2となる。よってr1=1、r2=false、r3=3。イは最初のpopで頂上の1ではなく底の6を返している。ウは満杯時に状態が変わらないという条件に反する。エは最後のpopで1個ではなく2個取り出した結果に相当する。

参考にした既存問題：IPA-FE-2025-KOUKAI-B-003。変更点：関数実装の空欄から、満杯時の不変性を含む操作列の追跡へ変更。

機械検査：1ケース。選択肢ごとの合格数（ア〜エ）：1 / 0 / 0 / 0。正答のみ全ケース一致。

操作列の独立モデル照合：

- push(6) → true、底から頂上：{6}、top=1
- push(1) → true、底から頂上：{6,1}、top=2
- pop() → 1、底から頂上：{6}、top=1
- push(8) → true、底から頂上：{6,8}、top=2
- push(3) → true、底から頂上：{6,8,3}、top=3
- push(9) → false、底から頂上：{6,8,3}、top=3
- pop() → 3、底から頂上：{6,8}、top=2

### 問4：正答 エ

列を外側のループで走査するので、(2,1,2)、(1,2,5)、(2,3,-1)の順に記録する。

第1列でmatrix[2,1]=2、第2列でmatrix[1,2]=5、第3列でmatrix[2,3]=-1を記録する。負数も0でなければ対象となる。したがって行番号{2,1,2}、列番号{1,2,3}、値{2,5,-1}でエ。アは行を外側として走査した順序。イは行番号配列と列番号配列を入れ替えている。ウは非零の負数-1を除外している。

参考にした既存問題：IPA-FE-2022-SAMPLE-B-004。変更点：行優先から列優先へ変更。長方形行列と負数を使い、走査順と非零条件を問う。

機械検査：1ケース。選択肢ごとの合格数（ア〜エ）：0 / 0 / 0 / 1。正答のみ全ケース一致。

### 問5：正答 イ

Ⅰは閲覧者の制限、Ⅲは削除禁止に違反する。ⅡとⅣの違反は今回の指定範囲外。

Ⅰでは運用担当者以外もログを閲覧できるので規則(2)違反。Ⅲでは担当者が記録済みログを削除できるので規則(3)違反。Ⅱは規則(1)、Ⅳは規則(4)には違反するが、問われた(2)(3)には違反しない。よってイだけが必要な全項目を過不足なく挙げている。複製先でも閲覧制限が必要であり、元の保管庫の制限だけでは足りない。180日という期間は本問の架空の社内規則であり、一般的な法定保存期間を意味しない。

参考にした既存問題：IPA-FE-2026-KOUKAI-B-006。変更点：独自の社内規則・4運用案へ再構成し、アクセス制御と改ざん防止に対象を限定。

機械検査：1ケース。選択肢ごとの合格数（ア〜エ）：0 / 1 / 0 / 0。正答のみ全ケース一致。

### 問6：正答 イ

水曜00:00まで復元できるので損失は10時間。フル2時間と増分3回の計3時間で、両目標を満たす。

最新の復元時点は水曜日00:00であり、水曜日10:00との差は10時間。日曜フルに月曜・火曜・水曜の増分を順に適用するため、2時間+20分×3=3時間となる。10≦12なのでRPOを、3≦4なのでRTOを満たし、イが正しい。アは最新の増分1回だけで復元できると誤解している。ウは水曜の増分を使わず火曜00:00までしか復元しない計算。エは3時間がRTO=4時間以内である点を誤判定している。増分バックアップと、フル以降の変更をまとめる差分バックアップは区別する。

参考にした既存問題：IPA-FE-2025-KOUKAI-B-006。変更点：独自の日程・復元時間・RPO/RTOへ変更し、バックアップ連鎖と二つの目標を同時に判定する。

機械検査：1ケース。選択肢ごとの合格数（ア〜エ）：0 / 1 / 0 / 0。正答のみ全ケース一致。

### 問7：正答 ア

DBMSはP社、独自アプリはD社、退職者アカウントの無効化はN社の担当。

本問で明示した契約を各指摘に対応付ける。①はDBMSなのでP社、②は独自WebアプリケーションなのでD社、③は利用者アカウント管理なのでN社であり、アが正しい。イは基盤と独自アプリの担当を混同している。ウは独自アプリも基盤会社が修正すると誤解している。エのT社は問題の発見・報告を担当するだけで実際の対処担当ではない。これは本問の契約条件による答えであり、PaaSという名称だけで全サービスの責任分界を一律に決めるものではない。
