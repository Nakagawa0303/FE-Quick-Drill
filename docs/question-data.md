# 問題データの調査結果と整備手順

確認日：2026-11-08。今回は問題を増やさず、追加経路と検証を整備した。

## 調査結果

| 要件 | 変更前 | 今回の対応 |
| --- | --- | --- |
| IPA／AIの区別 | `source.type` の `ipa` / `ai` / `original` で対応 | 維持。IPA問題の独自解説は `explanation.author` で区別 |
| ID・科目・大分野・出典・正答・二段階解説・検証状態 | すべて存在。`field` が大分野 | 空白のみの文字列や不正日付を拒否。IPA出典を構造化 |
| 科目B | `code` / `table` / `trace`、2〜20個の選択肢に対応 | 維持。表の形状、有限の数値、空表、重複選択肢を検査 |
| JSON一括追加 | 未対応。学習履歴のJSON復元だけ存在 | 開発者向け追加JSONと検査・変換コマンドを追加 |
| 重複・正答不整合・欠落検出 | ID重複、正答の添字範囲、必須項目は検査済み | 内容重複、公式出典の重複、公式記号と正答、確認記録と正答の不一致を追加 |
| 未検証AIの除外 | `verified` だけ通常演習・復習に出題 | 維持し回帰テスト。検査処理は検証状態を昇格しない |

既存16問のID・選択肢・正答・検証状態、保存形式version 1は変更していない。既存の `verification.method/date` は初期サンプル時の開発チェックの記録として扱う。今回、追加の人手レビューを行ったことにはしない。追加バンクには旧形式の検証記録だけでは登録できない。

## JSON一括追加

1. `data/additional-questions.json` の `questions` 配列に問題をまとめて追記する。
2. `npm run questions:build` で全件検査し、合格時だけ `data/additional-questions.js` を生成する。
3. `npm run questions:check` でJSON・既存サンプル・生成物の一致を確認する。
4. `npm test` と少数問題の画面確認を行い、JSONと生成JSを一緒にコミットする。

Node.js 20以上、追加パッケージ不要。`node scripts/build-questions.js --write` / `--check` でも実行できる。実行場所に依存せず、このリポジトリのJSONを読む。ブラウザで利用するときのビルドや外部通信は増えない。以下は空の追加バンクの形式例であり、現在の収録数はREADMEを参照する。

```json
{
  "version": 1,
  "questions": []
}
```

これは**開発者による収録データの更新**。学習記録画面のJSON復元にこのファイルを渡しても取り込めない。問題追加を利用者のブラウザ保存へ混ぜない。生成JSを直接編集せず、今後の追加・検証状態の変更はJSONを編集して再生成する。

配列の一部でも不正なら生成しない。全件のエラーを問題IDとフィールド名付きで報告する。IDは英数字で始まり英数字・`-`・`_`のみ。既存IDを再利用しない。既存の正答・選択肢順序を変更すると学習履歴に影響するため、そのような訂正は履歴移行を別途設計すること。新IDにすれば同じ内容の二重収録が許されるわけではない。

## 追加問題の形式

全問題で `id`, `subject`, `field`, `prompt`, `choices`, `answer`, `explanation.brief/detail`, `source.type/title`, `verification.status` が必須。分類辞書は `js/classification.js` に集約し、coreとappが共有する（coreは互換性のためFIELDSを再export）。

新規科目A問題は `subfield` 必須。親の `field` 配下にある正確な名称を指定する。小分野はIPAシラバスVer.9.2の中分類相当で、公式の小分類ではない。旧バンクを直接読む `validateQuestions` の既定動作では、プロパティ欠落だけ「未分類」へフォールバックする。空文字・null・未知名・親子不一致・科目Bへの付与は拒否する。「未分類」という値を新規問題へ書かず、分類できない候補は追加バンクの外で理由とともに保留する。`prepareQuestionBank`／questions:buildは新規Aの分類欠落も拒否する。履歴のitemsには分類を追加しない。

`answer` は**0始まりの整数**。確認前の正答候補・解説案が揃っていても `pending` とし、演習には出さない。候補も未入力の段階の作業メモは追加バンクの外で管理する。欠落項目を空白や「確認済み」の仮記録で埋めない。

次は形式説明用の未検証AIデータ。問題内容の正しさは保証せず、このまま収録しない。

```json
{
  "id": "AI-FE-A-TECH-0001",
  "subject": "A",
  "field": "テクノロジ",
  "subfield": "基礎理論",
  "prompt": "ここに問題文を記入",
  "choices": ["選択肢1", "選択肢2"],
  "answer": 0,
  "explanation": {"brief": "簡潔な解説案", "detail": "詳細な解説案"},
  "source": {"type": "ai", "title": "生成に使用したモデル・生成日・管理番号等"},
  "verification": {"status": "pending"}
}
```

### 検証済みへの変更

新規収録の `verified` には、従来の `method` / `date` に加え、次の `review` が必要。確認を実施した本人が、実際の記録を記入する。テンプレートをコピーして自動的にtrueにしない。

| 項目 | 内容 |
| --- | --- |
| `reviewer` | 確認担当者の識別子 |
| `reference` | 公式解答のURL・該当箇所、または独立計算・参考資料等の追跡可能な根拠 |
| `answerIndex` | 確認した正答の0始まり添字。`answer` と一致必須 |
| `answerChecked` | 正答の正しさ・一意性を確認した場合のみtrue |
| `explanationChecked` | 簡潔・詳細の両解説と各選択肢の整合性を確認した場合のみtrue |
| `transcriptionChecked` | IPAの場合必須。本文・選択肢・図表・疑似言語を原本と照合した場合のみtrue |
| `traceChecked` | トレース表がある場合必須。全行を独立計算で照合した場合のみtrue |

`verification.date` は `YYYY-MM-DD` の実在日付。`method` には確認手段と結果を記録する。公式問題でも、公式正答の照合だけで独自解説を検証済みにしない。どれかが未確認なら `pending` のままにする。

自動検査は**記録の形式と相互整合性**を検査する。文章の意味、正答の一意性、公式PDFと転記内容の一致、レビューを本当に実施したかは判定できない。falseをtrueに書き換えただけでは内容の検証にならない。

## IPA公式問題の出典設計

`source.type = "ipa"` では以下を必須にする。

| 項目 | 記録例／意味 |
| --- | --- |
| `title` | 元資料の正式な名称 |
| `year` | 西暦年度の整数 |
| `session` | 公開問題／サンプル問題など、資料の区別 |
| `exam` | `FE` |
| `section` | `科目A` または `科目B`。問題のsubjectと一致 |
| `questionNumber` | 原本の問番号の整数 |
| `url` | IPA公式の問題冊子PDF URL |
| `answerUrl` | 同じ年度・区分の公式解答例PDF URL |
| `termsUrl` | 収録時に確認したIPA公式利用条件・FAQのURL |
| `accessedAt` | URL・条件を確認した日付 |
| `modified` | 本文・選択肢等を改変したかのboolean |
| `modificationNote` | modifiedがtrueなら改変箇所・内容を必須記録 |
| `answerKey` | 公式解答を確認後、`{"label":"ウ","index":2}` のように記録。verifiedでは必須 |

`choiceLabels` に原本の選択肢記号を順番どおり記録する（例：`["ア","イ","ウ","エ"]`）。`answerKey.label` と `choiceLabels[answerKey.index]`、`answerKey.index` と `answer` を照合する。選択肢数は科目Bも固定しない。

独自解説には `explanation.author`（例：作成者、AI下書きの有無）を必須記録し、IPA公式解説と誤認させない。結果画面には構造化項目から年度・資料区分・試験区分・科目・問番号を表示し、改変内容、問題・解答例・利用条件へのリンク、解説作成主体も表示する。

現段階は2023年度以降の科目A/B公開問題を対象に設計している。旧制度の午前・午後や複数設問を持つ大問を、そのまま科目Bとみなさない。画像が解答に必須の問題や複雑な複数空欄の問題は、現在の本文・コード・単一表・単一正答形式で忠実に表現できるか別途確認し、対応できなければ収録を保留する。

- [2026年度（令和8年度）の問題冊子・解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/sg_fe/koukai/2026r08.html)：2026年7月1日公開。FE科目A/Bそれぞれの問題冊子・解答例への掲載リンクを確認した。今回、個々の問題の正答・解説を検証したことは意味しない。
- [IPA 試験に関するよくある質問「その他」](https://www.ipa.go.jp/shiken/faq.html)：公開過去問の使用条件。教育目的など制度の意義に反しない使用は原則として許諾・使用料不要。ただし著作権は放棄されていない。年度、期、試験区分、時間区分、問番号等の出典を明記し、改変した場合はその旨も明記する。IPAが提供する電子データは公開PDF。

これらは確認時点の公式案内の要約であり、収録時には元ページを再確認する。非公開問題や第三者サイトの独自解説は、公開過去問と同じ条件で使えるとは扱わない。

## 最初のIPA収録バッチの提案

1. 年度ページを一つ選び、科目A/Bそれぞれ問題冊子と解答例のURL・資料名を台帳に記録する。公開問題とサンプル問題は別セットとして扱う。
2. まず科目A2〜3問、科目B1問で転記工程を検証する。IDは例 `IPA-FE-2025-KOUKAI-A-001` とし、年度・資料区分・科目・原問番号から安定して付与する。
3. 本文・選択肢・疑似言語・表を原本どおり転記する。原本の記号と画面上の数字の対応を保存する。OCR結果は必ず原本と照合する。必要な図を省略して問題を成立させない。
4. `pending` で登録。公式解答例の年度・科目・原問番号を照合し、正答記号と添字を二重確認する。作成者は独立に解き、簡潔・詳細の解説を用意する。科目Bのトレースは実行または独立計算で確認する。
5. 別の確認担当者が原本との一致、正答・解説・トレースをレビューする。担当者と根拠を記録し、完了分だけ `verified` にする。一人で行う場合も転記とレビューを別工程にし、その事実を明示する。
6. 自動検査・既存機能のテスト後、演習と結果画面で長文、インデント、表、選択肢、出典・改変表示を確認する。問題の追加数より、誤りを検出できる工程を優先する。

重複は、同一ID、年度等の公式出典タプル、正規化した本文＋選択肢集合＋コード＋表の一致で検出する。別ID・選択肢順だけ変更した再登録も拒否する。全半角・空白差は本文と選択肢で吸収するが、コードの字下げは保持する。表現を大きく変えた類似問題や画像内の一致は自動検出しないので、人のレビューも必要。
